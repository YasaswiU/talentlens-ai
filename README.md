# TalentLens AI

**AI-Powered Recruitment & Skill Gap Analysis**
*Using Natural Language Processing and Machine Learning*

TalentLens AI is a recruitment **decision-support** platform. It helps recruiters
automatically process resumes, extract technical skills, match candidates to job
descriptions, identify skill gaps, evaluate candidates with a local LLM, run a
skill-based quiz, predict likely hiring outcomes, and rank candidates.

> **TalentLens AI does not make autonomous hiring decisions.** Every prediction and
> score is shown with a full breakdown, and the recruiter always makes the final
> Approve / Reject call.

---

## 1. Project Overview

Candidates register, upload a resume (PDF), and apply to job postings. The system
extracts text and skills from the resume, evaluates it with a local LLM, computes a
resume-to-job match score, identifies missing skills, generates a 5-question
adaptive quiz from the candidate's own skills, and predicts a likely outcome using a
Random Forest model trained on synthetic data. Recruiters see all of this in a
ranked dashboard and make the final call.

## 2. Features

**Candidate**
- Register / login, profile with experience
- Upload resume PDF → automatic text extraction, skill extraction, AI evaluation
- Browse and apply to open jobs
- View match %, skill gaps, quiz score, predicted outcome
- Career-AI chat for questions like "What skills am I missing?"

**Recruiter**
- Create job postings with required skills and minimum experience
- View all candidates, resumes, scores, and skill gaps in one table
- Search / filter / sort candidates, view ranked leaderboard
- Approve / Reject / Pending actions per candidate
- Export candidate data to CSV
- View model accuracy, precision, recall, and feature importance
- Read the documented Limitations of the system

## 3. Architecture

```
Presentation Layer   → Jinja2 templates, candidate portal, recruiter dashboard, Career-AI chat
Application Layer    → Flask routes, session auth, role-based access, uploads, CSV export
Intelligence Layer   → spaCy, TF-IDF + cosine similarity, Random Forest, Ollama + Gemma 3 4B
Data Layer           → SQLite, trained model.pkl, uploaded resumes
```

## 4. Technologies

| Layer | Technology |
|---|---|
| Backend | Python, Flask, SQLite, Jinja2 |
| NLP | spaCy (with an automatic fallback tokenizer if spaCy isn't installed) |
| Resume parsing | pdfplumber |

| LLM | Ollama + Gemma 3 4B |

## 6. Installation (Windows)

```powershell
# 1. Create and activate a virtual environment
python -m venv venv
venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Install the spaCy English model
python -m spacy download en_core_web_sm
```

> **Note on spaCy:** `services/skill_extractor.py` tries to load spaCy +
> `en_core_web_sm` first. If either is missing (e.g. in an offline environment),
> it automatically falls back to a lightweight vocabulary/regex matcher that
> produces the same output format, so the app still runs — but for full marks on
> the "uses spaCy tokens and noun chunks" requirement, make sure step 3 above
> completes successfully.

## 8. Train the Random Forest Model

```powershell
python train_model.py
```

This generates a **synthetic** 1,000-row dataset (350 selected / 650 not selected),
trains a `RandomForestClassifier(n_estimators=100, max_depth=10)` on
`[experience, skills_count, quiz_score]`, and saves:
- `model.pkl` — the trained model
- `model_metrics.json` — actual accuracy / precision / recall / 5-fold CV accuracy
- `static/images/feature_importance.png` — feature importance chart

The numbers printed are **calculated by the actual training run**, not
hard-coded. On a typical run they land close to (but not identical to) the
spec's reference figures of ~84.5% accuracy / 0.83 precision / 0.70 recall /
84.4% CV accuracy — exact values vary by run due to random sampling.

## 9. Install & Run Ollama + Gemma 3 4B (optional but recommended)

The app works without Ollama — resume evaluation and Career-AI chat will show a
clear "unavailable" message instead of crashing. To enable AI resume scoring:

```powershell
# 1. Download and install Ollama from https://ollama.com
# 2. Pull the Gemma 3 4B model
ollama pull gemma3:4b

# 3. Start the Ollama server (usually starts automatically after install)
ollama serve
```

By default the app looks for Ollama at `http://localhost:11434`. Override with
the `OLLAMA_HOST` / `OLLAMA_MODEL` environment variables if needed.

## 12. Candidate Workflow

1. Register / log in as a candidate
2. Set your years of experience on the Profile page
3. Upload your resume (PDF) → text extraction → skill extraction → AI evaluation
4. Browse open jobs and apply → get a TF-IDF match score and skill-gap breakdown
5. Take the 5-question adaptive quiz generated from your extracted skills
6. View your predicted outcome, final score breakdown, and Career-AI chat

## 13. Recruiter Workflow

1. Register / log in as a recruiter
2. Create job postings with a description, required skills, and minimum experience
3. Review candidates as they apply: resume score, match %, quiz score, prediction
4. Open a candidate's detail page to see the full score breakdown and skill comparison
5. Approve / Reject / mark Pending
6. View the Ranked Candidates leaderboard, filterable by job
7. Export candidate data to CSV
8. Review model accuracy and feature importance on the Analytics page

## 14. ML Methodology

- **Job matching:** `TfidfVectorizer` (English stop-words removed) vectorizes the
  resume text and job description; `cosine_similarity` computes
  `sim(R,J) = (R·J) / (‖R‖‖J‖)`, converted to a percentage.
- **Skill extraction:** resume text is lowercased and matched against a fixed
  40-term technical vocabulary using spaCy's `PhraseMatcher` over tokens and
  multi-word phrases (or the fallback matcher if spaCy is unavailable).
- **Outcome prediction:** `RandomForestClassifier(n_estimators=100, max_depth=10)`
  trained on `[experience, skills_count, quiz_score]` → `selected ∈ {0,1}`.
- **Final score:** `0.40×MatchScore + 0.30×QuizScore + 0.20×SkillsScore + 0.10×ExperienceScore`,
  with every component and its weighted contribution shown on the candidate detail page.

## 15. Evaluation Metrics

Run `python train_model.py` to (re)generate real metrics. They are also shown on
the Recruiter → Analytics page. Example output from a training run in this
environment:

```
Accuracy:            80.50%
Precision:           0.81
Recall:              0.65
5-fold CV Accuracy:  81.40%
```

These will vary slightly each time you retrain due to random sampling in the
synthetic dataset generator (a fixed random seed is used, so the numbers are
reproducible per-run but not guaranteed to exactly match any other run's
environment/library versions).

## 16. Limitations

1. The Random Forest training data is **synthetic** — it has not been validated
   against real hiring outcomes.
2. TF-IDF matching is lexical and may miss synonyms or paraphrased skills (e.g.
   "ML" vs. "machine learning" unless both appear literally).
3. Skill extraction currently depends on a fixed 40-term vocabulary — skills
   outside that list are not detected.
4. LLM output (Gemma 3 4B via Ollama) can vary between runs.
5. No fairness/bias audit has been performed on the prediction model.

## Security Notes

- Passwords are hashed with Werkzeug's `generate_password_hash` (never stored in plaintext)
- Sessions are server-side via Flask's signed session cookies
- Uploads are restricted to `.pdf`, capped at 5 MB, and saved with sanitized filenames
- Candidate and recruiter routes are protected by role checks; a candidate cannot
  open a recruiter URL and vice versa
- All resume-parsing and LLM-calling code is wrapped in try/except so a bad PDF or
  an offline Ollama server returns a friendly message instead of a stack trace
